# Odin Guild App UI 디자인 가이드

> 상태: 기본 UI 기준
>
> 기준일: 2026-08-10
>
> 적용 대상: Flutter 모바일·태블릿 앱

## 1. 목적

이 문서는 Odin Guild App의 화면을 생성하거나 수정할 때 따라야 하는 기본 디자인 원칙과 UI 토큰을 정의한다. 이후 모든 UI 작업은 이 문서를 시각적 source of truth로 사용한다.

기능·권한·API 범위는 `flutter-frontend-architecture.md`를 따르고, 화면의 색상·타이포그래피·간격·컴포넌트·상호작용은 이 문서를 따른다.

## 2. 디자인 방향

### 2.1 핵심 콘셉트

**세 가지 테마를 가진 단정한 생활형 길드 관리 앱**

토스의 명확한 정보 계층과 당근의 친근하고 쉬운 사용성을 참고하되, 특정 서비스의 화면·아이콘·브랜드 요소를 그대로 복제하지 않는다.

이 앱은 게임 홍보 앱이 아니라 매일 반복해서 사용하는 길드 운영 도구다. 게임 분위기는 보스명과 기능 자체에서 자연스럽게 드러내고, 화면은 일반적인 금융·생활 앱처럼 정돈한다.

### 2.2 반드시 지킬 원칙

- 기존 `Sand Gold`와 `Dark Blue` 테마를 유지하고, 앱 아이콘 기반 `Icon Purple` 테마를 추가로 제공한다.
- 앱 기본값은 앱 아이콘의 보라색을 활용한 `Icon Purple`이며 사용자의 선택을 기기에 저장한다.
- 한 화면에는 하나의 가장 중요한 행동만 강하게 강조한다.
- 보스명, 시간, 남은 시간, 참여 상태의 우선순위를 명확히 한다.
- 긴 설명보다 짧은 제목, 상태 문구, 다음 행동을 먼저 보여준다.
- 카드 전체를 여러 색으로 칠하지 않고 태그와 상태 텍스트에만 색상을 사용한다.
- 그림자와 선보다 여백, 배경색 차이, 타이포그래피로 영역을 구분한다.
- 운영진 기능은 일반 사용자 흐름에서 한 단계 안쪽에 배치한다.
- 모든 주요 기능은 한 손 조작이 가능한 위치와 크기로 제공한다.

### 2.3 사용하지 않는 표현

- 북유럽 문양, 룬 문자, 방패·도끼 등 장식성 이미지
- 금속·가죽·돌 질감 배경
- 과도한 금색 테두리와 반짝임을 사용한 게임 UI
- 네온 효과, 강한 발광, glassmorphism
- 과도한 gradient와 깊은 그림자
- 카드마다 서로 다른 강조색 사용
- 작은 글씨로 정보를 과도하게 압축한 테이블
- 공식 게임 로고, 캐릭터, 아이템 이미지를 허가 없이 사용

### 3.2 타이포그래피

기본 글꼴은 앱에 포함한 `Pretendard`를 사용한다. 사용할 수 없는 환경에서는 `Noto Sans KR`, Android/iOS 시스템 글꼴 순으로 fallback한다.

| Style | 크기/행간 | 굵기 | 용도 |
| --- | --- | --- | --- |
| `display` | 28/36 | 700 | 홈 핵심 숫자, 다음 보스 |
| `pageTitle` | 24/32 | 700 | 화면 제목 |
| `sectionTitle` | 20/28 | 700 | 섹션 제목 |
| `cardTitle` | 17/24 | 600 | 보스명, 길드원명 |
| `body` | 16/24 | 400 | 본문과 입력값 |
| `bodyStrong` | 16/24 | 600 | 주요 상태와 버튼 |
| `label` | 14/20 | 500 | tag, 필드 label, 보조 버튼 |
| `caption` | 12/18 | 400 | 수정 시각, 설명 |

- 숫자 시각과 카운트다운은 tabular figures를 적용한다.
- 본문에 14px 미만 글자를 사용하지 않는다. 12px은 부가 정보에만 사용한다.
- 한 화면에서 700 이상의 굵기를 남용하지 않는다.

### 3.3 간격

4px 기반 spacing scale을 사용한다.

| Token | 값 | 사용 예 |
| --- | --- | --- |
| `space1` | 4 | 아이콘과 짧은 label |
| `space2` | 8 | 행 내부 요소 |
| `space3` | 12 | 카드 내부 작은 간격 |
| `space4` | 16 | 기본 padding |
| `space5` | 20 | 화면 좌우 padding |
| `space6` | 24 | 섹션 간격 |
| `space8` | 32 | 큰 섹션 분리 |
| `space10` | 40 | 화면 상단 여백 |

모바일 화면의 기본 좌우 여백은 20px이다. 작은 화면에서도 16px 아래로 줄이지 않는다.

### 3.4 모서리와 높이

| 요소 | 값 |
| --- | --- |
| 작은 tag | 8px |
| 입력·일반 버튼 | 10~12px |
| 카드 | 14px |
| 바텀시트 | 상단 20px |
| 기본 버튼 높이 | 52px |
| 보조 버튼 높이 | 44px |
| 최소 터치 영역 | 48×48px |

### 3.5 그림자와 구분선

- 기본 카드는 테마 surface와 1px 이하의 은은한 테두리로 구분한다.
- floating 요소와 바텀시트에만 매우 약한 그림자를 사용한다.
- 목록의 모든 행에 선을 넣지 않는다. 필요한 경우 행 사이 간격 또는 마지막을 제외한 얇은 divider를 사용한다.
- 그림자가 필요한 경우 투명도 8% 이하의 중립색을 사용한다.

## 4. 앱 구조

### 4.1 하단 내비게이션

하단 내비게이션은 다음 4개를 기본으로 한다.

1. 홈
2. 일정
3. 투표
4. 전체

공지, 손지원, 컬렉션, 콘텐츠 그룹, 공성전, 길드원, 프로필, 설정은 `전체` 화면에 그룹형 목록으로 배치한다.

- 아이콘과 한글 label을 항상 함께 표시한다.
- 현재 탭은 `primary`, 비활성 탭은 `textTertiary`를 사용한다.
- 탭 안에서 상세 화면으로 이동해도 하단 탭 상태를 유지한다.
- 중앙 FAB가 내비게이션을 침범하는 구조는 사용하지 않는다.

### 4.2 화면 공통 구조

```text
SafeArea
└── Scaffold
    ├── AppBar 또는 화면 제목
    ├── Optional summary 영역
    ├── Optional filter/chip 영역
    ├── Scrollable content
    └── BottomNavigationBar 또는 고정 CTA
```

- 제목만 있는 화면은 app bar 배경을 화면과 동일하게 처리한다.
- 스크롤 시 제목이 갑자기 사라지지 않도록 큰 제목에서 작은 app bar 제목으로 자연스럽게 전환할 수 있다.
- 새로고침은 pull-to-refresh를 기본으로 제공한다.

### 4.3 로그인·회원가입

- 회원가입 화면은 `기존 길드 가입`과 `새 길드 생성`을 segmented control로 선택하게 한다.
- 기존 길드 가입을 선택하면 가입 코드만 입력하고, 새 길드 생성을 선택하면 길드 이름을 입력한다.
- 새 길드 생성 시 계정이 마스터가 된다는 결과를 입력 영역 가까이에 짧게 안내한다.
- 선택하지 않은 흐름의 입력 필드는 숨겨서 사용자가 불필요한 코드를 입력하지 않게 한다.

## 5. 공통 컴포넌트

### 5.1 버튼

#### Primary button

- 화면의 가장 중요한 행동에만 사용한다.
- 배경 `primary`, 글자 흰색, 높이 52px
- 한 화면에서 동시에 하나만 강하게 노출한다.
- 예: 로그인, 참여하기, 저장, 일정 등록 완료

#### Secondary button

- 흰색 또는 `surfaceSubtle` 배경과 `textPrimary` 글자
- 예: 참여자 보기, 필터 초기화, 취소

#### Text button

- 목록의 작은 보조 행동에 사용
- 예: 더보기, 수정, 재시도

#### Destructive button

- `danger` 사용
- 일반 버튼 옆에 항상 노출하지 않고 확인 다이얼로그나 overflow 메뉴 안에 배치
- 예: 삭제, 전체 초기화, 강퇴

### 5.2 카드

- 기본 배경은 `surface`
- radius 14px, padding 16~20px
- 카드 전체를 눌렀을 때 상세 화면으로 이동한다면 카드 내부에 중복 화살표 버튼을 추가하지 않는다.
- 카드 안의 정보 순서는 제목 → 핵심 값/상태 → 보조 정보 → 행동 순서로 배치한다.

### 5.3 입력 필드

- field label은 입력 영역 위에 표시한다.
- placeholder로 label을 대신하지 않는다.
- 기본 배경 `surfaceSubtle`, border는 평소 생략 가능
- focus 상태에만 `primary` border 또는 focus ring을 표시한다.
- 오류는 입력 아래에 짧은 문장으로 표시한다.
- 숫자 입력에는 단위와 천 단위 formatting을 제공한다.

### 5.4 Chip과 tag

- filter chip은 선택 가능한 컴포넌트다.
- status tag는 상태를 보여주는 읽기 전용 컴포넌트다.
- 색상만으로 상태를 구분하지 않고 반드시 텍스트를 함께 표시한다.
- 화면에 동시에 5개 이상의 강한 색상 tag를 노출하지 않는다.

### 5.5 바텀시트

다음 상황에서 사용한다.

- 일정 등록 방식 선택
- 보스 일정 관리 메뉴
- 참여자 목록
- 필터와 정렬
- 길드원 상세의 빠른 행동

복잡한 다단계 양식은 바텀시트에 억지로 넣지 않고 별도 화면으로 이동한다.

### 5.6 다이얼로그

다음 destructive action에만 사용한다.

- 일정 전체 초기화
- 투표 삭제
- 컬렉션 삭제
- 길드원 강퇴
- 공성전 데이터 전체 초기화

다이얼로그에는 대상, 영향 범위, 되돌릴 수 있는지 여부를 명확히 적는다.

## 6. 주요 화면 기준

### 6.1 홈

정보 우선순위는 다음과 같다.

1. 다음 보스
2. 오늘 일정·투표 요약
3. 중요한 공지
4. 자주 사용하는 기능

```text
안녕하세요, 사용자님
오늘 길드 일정을 확인해 보세요

다음 보스
파르바
오후 9:40 · 12분 남음
                            참여하기

오늘의 길드
일정 12개   투표 4개   손지원 2개

공지사항
이번 주 길드 운영 안내              >
```

- 메뉴 아이콘을 큰 격자로 전부 나열하지 않는다.
- 요약 API가 없다면 호출 수가 과도해지지 않도록 필수 정보만 표시한다.
- 운영진에게는 `일정 등록` 등의 빠른 행동을 별도 영역으로 제공한다.

### 6.2 보스 일정

토스의 거래내역처럼 시간순 목록을 사용한다.

```text
보스 일정                         등록

[전체] [본섭] [침공] [공통] [고정]

오늘

오후 9:40
파르바                           12분 남음
요툰하임 · 본섭                    참여 8명

오후 10:00
성채 7층                         32분 남음
고정 일정
```

- 시간, 보스명, 남은 시간 순으로 강조한다.
- 10분 이내 일정은 남은 시간만 `warning`으로 표시한다.
- 일정 카드 전체를 경고색으로 칠하지 않는다.
- 일반 사용자의 주요 행동은 참여하기다.
- 컷, 멍, 개별 삭제는 모든 활성 길드원의 일정 카드 또는 관리 바텀시트에 배치한다.
- 일정 등록은 app bar의 `등록` 또는 화면 하단 고정 CTA로 제공한다.

#### 원본 스케줄 기능 유지 기준

- 목록 상단에 초 단위 서버 시각과 30초 자동 동기화 상태를 표시한다.
- 유형 필터는 `공통`, `본섭`, `침공`, `고정`을 동시에 여러 개 선택할 수 있어야 한다.
- 일반 보스는 출현 후 컷 또는 삭제 전까지 유지하고, 고정 일정은 최근 지난 일정 1개만 유지한다.
- 다음으로 출현할 보스는 테두리와 `다음 보스` 문구로만 강조한다.
- 30분 이상 빈 구간은 `휴식 시간` 행으로 구분한다.
- 상세 보기에는 참여, 컷, 멍 등의 빠른 행동을 제공하고 간략 보기에서는 핵심 시간과 보스명만 남긴다.
- 일반 보스의 `컷`은 쿨타임을 계산해 다음 젠을 생성하지만, 침공 보스의 `종료`는 현재 일정만 삭제한다.
- `멍`은 출현 시각이 지난 일반 보스에만 제공한다.
- 고정 일정은 서버의 보스 정의에 저장된 시각과 요일을 기준으로 오늘·내일 일정을 자동 생성한다.
- 음성 알림은 사용자가 켜고 끌 수 있으며 포그라운드에서 5분 전, 1분 전, 출현 시점에 안내한다.

#### 보스 시간 입력

- 기본 입력은 지역별 accordion과 `기준 시각 + 보스별 남은 시간` 방식이다.
- `2410`은 24분 10초, `013020`은 1시간 30분 20초로 해석하며 `1시간 5분` 같은 한글 단위도 지원한다.
- 기준 시각을 비우면 동기화된 서버 현재 시각을 사용한다.
- 입력 중인 값은 날짜별 기기 초안으로 저장하고 서버에는 `지역 적용` 또는 `전체 적용` 시점에만 전송한다.
- 오늘 자정을 넘는 침공 계산 결과는 등록하지 않고 제외 건수를 안내한다.
- 정확한 출현 시각을 아는 경우 `한 건` 입력을 별도로 제공한다.
- 길드장에게는 스크린샷 선택, OCR 템플릿 선택, 인식 결과 확인, 서버 선택, 최종 등록 순서의 OCR 흐름을 제공한다.
- 참여 보스 설정은 본섭·침공 등 보스 유형별 그룹으로 나누고, 같은 이름의 보스도 보스 정의별로 독립 선택할 수 있게 한다. 보스 정의 추가·삭제·기본값 복구는 운영 기능으로 분리하되 입력 화면에서 접근할 수 있게 한다.

### 6.3 보스 참여 투표

```text
보스 참여 투표

[오늘] [내일]

파르바
오후 9:40 · 요툰하임
현재 8명 참여

참여자 보기                    참여하기
```

- 참여 전에는 `참여하기`를 primary로 표시한다.
- 참여 후에는 초록색 체크 아이콘과 `참여 완료`를 사용한다.
- 참여 취소는 참여 완료 버튼을 다시 누른 후 확인하거나 상세 메뉴에서 제공한다.
- 마감 상태는 회색 tag와 `참여 마감` 문구를 함께 표시한다.
- 운영진에게만 app bar의 `수동 투표 추가` action을 표시하고, 보스명·유형·지역·출현
  날짜·시각·축 여부를 모바일 바텀시트에서 입력하게 한다.
- 수동 등록이 성공하면 바텀시트를 닫고 목록을 다시 조회하며, 일반 길드원에게는 해당
  관리 action을 노출하지 않는다.
- 운영진의 마감·삭제·통계는 `관리` 메뉴로 분리한다.

### 6.4 공지

- 길드룰, 가격표, 보스 통제 탭을 사용한다.
- 상단 요약 카드에는 공지의 목적, 읽기 전용/관리 가능 상태, 현재 길드장·운영진을 표시한다.
- 긴 규칙은 제목과 핵심 요약을 먼저 보여주고 접기/펼치기를 제공한다.
- 운영진의 등록은 app bar에 배치하고 수정·삭제는 각 카드의 overflow 메뉴에 배치한다.
- 길드룰 순서 변경은 overflow 메뉴의 위로·아래로 이동으로 제공하고 저장 실패 시 기존 순서로 복구한다.
- 가격표는 섹션별 아이템과 가격을 좌우로 정렬하고 숫자 가격에는 천 단위 구분을 적용한다.
- 공지 편집은 모바일 전체 높이 바텀시트에서 제목·허용 색상·섹션·항목을 순서대로 입력한다.
- 보스 통제 상태는 색상 tag와 상태 문구를 함께 표시한다.
- 운영진이 보스 tag를 누르면 `통제 없음 → 동맹 한정 → 통제` 순서로 변경하며 처리 중인 보스만 로딩 상태로 표시한다.
- 서버의 임의 색상 문자열을 직접 렌더링하지 않고 앱에서 허용한 색상표로 제한한다.

### 6.5 손지원

- 상단 요약 카드에 모집중, 매칭완료, 내 활동 건수를 표시하고 접속 정보는 개인 연락으로만 공유한다는 보안 안내를 둔다.
- `진행중/내 활동/종료` segmented filter를 사용한다. 진행중은 OPEN·MATCHED, 종료는 DONE·CANCELED를 묶고 내 활동은 본인이 등록하거나 신청한 요청을 모두 포함한다.
- 요청 카드는 요청자, 주클래스, 전투력, 요청 날짜·시간, 상태, 메모, 신청자 수를 한눈에 표시한다. 직업은 노출하지 않는다.
- 주클래스와 전투력은 각각 독립된 정보 타일로 배치하고 전투력은 primary 색상과 굵은 숫자로 강조한다.
- 본인 요청은 primary 테두리와 `내 요청` 문구로 구분하되 카드 전체를 강한 색으로 채우지 않는다.
- 요청 등록은 floating action button에서 bottom sheet로 열고 날짜, 종일 여부 또는 시작·종료 시각, 500자 메모를 입력한다. 시간은 5분 단위로 정규화한다.
- 신청자는 닉네임 아래에 주클래스와 전투력을 별도 label·value로 표시한다. 선택 여부를 먼저, 나머지는 전투력 내림차순으로 배치해 요청자가 담당자를 비교하기 쉽게 한다.
- 요청 카드에서는 신청자 최대 3명만 미리 보여준다. 4명 이상은 `지원자 전체 보기` bottom sheet의 지연 생성 목록으로 제공해 50명이 신청해도 카드가 길어지지 않게 한다.
- 다른 길드원의 OPEN 요청이고 아직 신청하지 않은 사용자에게만 `손지원 신청` primary button을 표시한다.
- 본인 신청에는 취소 버튼을 제공하며 선택된 신청을 취소하면 요청이 다시 모집중으로 바뀐다는 영향을 확인 dialog에 명시한다.
- 요청자와 MASTER·ADMIN은 신청자 선택, 완료·취소·재모집·삭제를 사용할 수 있다. 삭제 확인에는 신청 내역도 함께 영구 삭제됨을 명시한다.
- 신청·선택·상태 변경 중에는 화면 전체를 막지 않고 해당 요청 카드의 동작만 비활성화한다.
- 목록은 `CustomScrollView`의 지연 생성 sliver와 pull-to-refresh를 사용한다.

### 6.6 아이템 컬렉션

모바일에서는 전체 길드원 비교표보다 개인 중심 화면을 우선한다.

- 상단 길드원 선택
- 컬렉션 검색과 filter
- 컬렉션별 accordion
- 아이템명과 부위, 오른쪽 완료 checkbox
- 태블릿에서만 전체 길드원 비교표 제공
- 완료 체크는 즉시 반영하되 저장 실패 시 원래 값으로 복구한다.
- 상단에는 전체 길드원 수, 아이템 수, 내 달성률을 요약하고 수동 새로고침 정책을 안내한다.
- 모바일은 `개인 현황`과 `길드 비교` 탭으로 구분하며 개인 현황을 기본으로 사용한다.
- 개인 현황은 길드원 선택과 달성 progress를 먼저 보여주고 컬렉션별 accordion 안에 아이템 체크를 배치한다.
- 길드 비교는 `길드원 기준`과 `아이템 기준`으로 나누며 분배 판단에 중요한 아이템 기준을 기본으로 사용한다.
- 길드원 기준은 전투력 내림차순으로 배치하고 순위, 닉네임, 전투력, 전체 달성률을 한 줄에서 비교한다. 펼친 카드에는 컬렉션별 progress를 표시한다.
- 아이템 기준 카드는 보유율, 보유·미보유 인원, 분배 1순위와 전투력만 요약해 길드원 수에 따라 카드 높이가 늘어나지 않게 한다.
- 전체 길드원 현황은 아이템 상세 bottom sheet에서 전투력 내림차순으로 표시하며 `전체/미보유/보유` 필터와 닉네임 검색을 제공한다. 50명 이상도 `ListView.builder` 계열의 지연 생성 목록을 사용한다.
- 아이템 상세 목록의 체크 변경 권한은 개인 현황과 동일하게 본인과 MASTER에게만 제공한다.
- 본인과 MASTER가 수정할 수 있는 체크만 활성화하고 읽기 전용 체크도 달성 여부를 명확하게 표시한다.
- 분배 1순위는 일반 미달성자를 먼저 표시하고 제외 길드원만 남으면 `후순위` 문구와 warning 색상을 사용한다.
- 컬렉션 추가·수정과 아이템 순서 변경은 전체 높이 바텀시트에서 처리한다.
- 우선순위 제외 관리는 운영진 전용 바텀시트에 길드원 switch 목록으로 제공한다.

### 6.7 콘텐츠 그룹

- 상단 요약에는 그룹 수, 편성 인원, 미편성 인원을 표시한다.
- 모바일은 `그룹`과 `미편성` 탭으로 구분하고 그룹 편성을 기본으로 사용한다.
- 태블릿은 좌측 길드원, 우측 그룹의 2열 구조를 사용한다.
- 그룹 카드는 그룹명, 인원, 합산 전투력과 전투력 순 길드원 최대 4명만 미리 표시한다. 전체 인원은 검색 가능한 상세 bottom sheet에서 확인한다.
- 미편성 길드원과 그룹 상세는 전투력 내림차순으로 표시하고 닉네임 검색을 제공한다.
- drag 중에는 저장하지 않고 drop 완료 시 한 번 저장한다.
- drag가 어려운 접근성 환경을 위해 `그룹으로 이동` 메뉴도 제공한다.
- MASTER·ADMIN만 그룹 생성·이름 변경·삭제·배치를 사용할 수 있으며 MEMBER에게는 읽기 전용 안내를 표시한다.

### 6.8 공성전

- 상단에 전체 시작 전·종료 후·사용 다이아 요약을 배치한다.
- 본인 입력 영역을 길드원 전체 목록보다 먼저 표시한다.
- 사용 다이아는 `시작 전 - 종료 후`로 계산해 양수로 표시한다.
- 본인 입력은 시작 전·종료 후 숫자 필드와 사용량 미리보기, 저장 버튼을 한 카드에 배치한다.
- 길드원 현황은 전투력 순 카드로 표시하고 시작 전·종료 후·사용량, 입력 여부, 마지막 수정 시각을 제공한다.
- 닉네임·클래스 검색과 `전체/입력/미입력` 필터를 제공하고 긴 목록은 지연 생성한다.
- 운영진 편집은 길드원 카드의 수정 버튼에서 별도 bottom sheet로 처리한다.
- 전체 초기화는 AppBar의 운영진 전용 action으로 제공하고 삭제 범위를 확인 dialog에 명시한다.
- 음수, 999,999,999 초과, 종료 후가 시작 전보다 큰 값은 저장 전에 오류 문구와 함께 차단한다.

### 6.9 길드원

모바일에서는 가로 표를 사용하지 않고 사람별 카드 또는 list tile을 사용한다.

```text
1위  사용자명
워리어 · 디펜더
전투력 123,456

치확 52.3% · 치저 41.2%
장비 및 스킬 보기                 >
```

- 기본 정렬은 전투력 순이다.
- 상단 요약 카드에는 전체 길드원 수와 운영진 수를 표시한다.
- 검색은 닉네임, 직업, 주클래스, 부계정 캐릭터명·클래스를 대상으로 한다.
- 검색 아래에 `캐릭터`, `장비`, `스킬` segmented comparison mode를 제공한다.
- 캐릭터 모드는 직업과 주클래스를 필터링하고 카드에서 부계정과 치확·치저·상적/충적을 비교한다.
- 장비 모드는 13부위 중 하나와 전체·일반·영웅·전설·신화·미입력 등급을 선택하고, 모든 카드의 같은 위치에 장비명과 등급을 표시한다.
- 스킬 모드는 액티브·패시브, 영웅 1~4·전설 1~2, 전체·습득·미습득 상태를 선택해 강화 수치를 길드원별로 비교한다.
- 비교 모드를 전환해도 검색어와 능력치 정렬은 유지한다.
- 정렬은 상단 버튼에서 바텀시트를 열어 전투력, 치확, 치저, 상적/충적과 높은 순·낮은 순을 선택한다.
- 목록 카드는 순위, 닉네임, 역할, 직업·주클래스, 전투력, 세 가지 능력치를 먼저 보여준다.
- 부계정이 있으면 캐릭터명과 주클래스를 카드 안의 연한 보조 영역으로 표시한다.
- 목록 하단에는 장비 입력 수와 스킬 습득 수를 요약하고, 전체 13부위 장비와 액티브·패시브 스킬은 상세 화면에서도 제공한다.
- 상세 화면은 캐릭터·부계정, 장비, 스킬 순서로 구성하고 장비 등급은 색상점과 텍스트를 함께 사용한다.
- 본인 카드는 primary 테두리와 `나` tag로 구분하되 카드 전체를 강한 색으로 칠하지 않는다.
- 역할 변경, 비밀번호 초기화, 강퇴는 권한이 있는 사용자에게만 overflow 메뉴로 제공한다.
- 강퇴 확인에는 컬렉션·그룹·공성전·참여 데이터가 함께 영구 삭제된다는 영향을 명시한다.
- 목록과 상세 화면 모두 pull-to-refresh를 제공하고 새로고침 중 기존 데이터를 유지한다.

### 6.10 프로필·설정

- 프로필 상단에는 아바타, 닉네임, 역할, 직업·주클래스, 전투력을 한 장의 요약 카드로 표시한다.
- 입력 영역은 `계정 정보`, `캐릭터 정보`, `부계정 정보`, `장비 정보`, `스킬 정보`의 accordion 카드로 나눈다.
- 최초 진입 시 계정과 캐릭터만 펼치고, 부계정·장비·스킬은 입력 현황을 subtitle로 보여준 채 접어 둔다.
- 아이디는 읽기 전용으로 표시하고 비밀번호는 변경할 때만 입력한다. 비밀번호를 비우면 기존 값을 유지한다.
- 전투력은 천 단위 구분 기호를 적용한다. 길드 정책으로 수정이 잠긴 경우 필드를 비활성화하고 잠긴 이유를 바로 아래에 안내한다.
- 최고 치명타 확률·최고 치명타 저항·상적/충적은 소수 입력과 `%` 단위를 제공한다.
- 부계정은 최대 1개만 입력하며 캐릭터명과 주클래스를 한 쌍으로 검증한다. 캐릭터명은 30자 이내로 제한한다.
- 장비는 무기부터 벨트까지 13부위를 모두 제공한다. 각 행은 등급을 색상점과 텍스트로 함께 표시하고 이름 또는 강화 수치를 입력한다.
- 스킬은 액티브·패시브 segmented control로 전환하며 영웅 4개, 전설 2개의 강화 상태를 각각 `X`, `0강`~`10강`으로 선택한다.
- 저장 CTA는 safe area 위 화면 하단에 고정하고 저장 중에는 버튼 내부 progress indicator를 표시한다.
- 저장 실패 시 accordion 상태와 입력값을 유지하며 오류 문구를 폼 하단 카드에 표시한다.
- 마스터 설정은 길드장에게만 메뉴와 화면을 노출하고 직접 경로 접근도 차단한다.
- 마스터 설정 상단에는 `길드장 전용` 상태 tag와 관리 범위를 안내하는 요약 카드를 배치한다.
- 길드 기본 설정은 길드 이름과 길드원 전투력 수정 허용 switch를 한 카드로 묶는다.
- 전투력 수정 switch의 현재 상태에 따라 내 정보 화면에 미치는 영향을 바로 아래 설명으로 바꿔 표시한다.
- 가입 코드는 일반 길드원·운영진 segmented control로 역할을 먼저 선택하고 현재 코드와 변경 입력을 한 카드에서 관리한다.
- 처음 저장할 때 코드를 비워두면 서버가 고정 랜덤 코드를 생성하고, 입력하면 마스터가 정한 코드로 저장한다.
- 가입 코드 입력칸 바로 아래에는 primary `가입 코드 저장` 버튼을 표시하고, 기존 코드와 달라졌을 때만 활성화한다.
- 운영진 코드 선택 시 운영 권한이 부여된다는 주의 문구를 함께 표시한다.
- 가입 코드는 역할 tag, 선택 가능한 코드, 복사 버튼, `만료 없음 · 변경 전까지 계속 사용` 안내를 함께 표시한다.
- 기존 코드를 변경할 때는 이전 코드가 즉시 폐기된다는 확인을 먼저 받는다.
- Discord 관련 필드와 상태는 설정 UI에 표시하지 않는다.

## 7. 상태 화면

### 7.1 Loading

- 첫 로딩에는 콘텐츠 형태와 비슷한 skeleton을 사용한다.
- 버튼 저장 중에는 버튼 안에 작은 progress indicator를 표시한다.
- 전체 화면 spinner만 장시간 표시하지 않는다.

### 7.2 Empty

- 데이터가 없다는 사실과 사용자가 할 수 있는 다음 행동을 함께 보여준다.
- 예: `등록된 일정이 없어요` + 로그인 사용자에게 `일정 등록` 버튼
- 장식용 일러스트는 필수가 아니며, 사용해도 단순한 자체 아이콘을 사용한다.

### 7.3 Error

- 기술적인 오류 메시지를 그대로 노출하지 않는다.
- 간단한 설명, 재시도 버튼, 필요한 경우 고객 대응용 오류 코드를 표시한다.
- 저장 실패 시 사용자가 입력한 값은 유지한다.

### 7.4 Offline

- 상단에 작은 offline banner를 표시한다.
- 캐시 데이터에는 `마지막 업데이트` 시각을 함께 보여준다.
- 온라인 복귀 시 자동 재조회하되 사용자가 작성 중인 양식은 초기화하지 않는다.

## 8. 운영진 UI 원칙

- 조회 화면은 일반 길드원과 동일하게 유지한다.
- 생성은 app bar 또는 화면 하단의 명확한 CTA로 제공한다.
- 수정은 카드 overflow 메뉴에 배치한다.
- 여러 항목을 수정할 때만 관리 모드로 전환한다.
- 삭제와 전체 초기화는 목록에 상시 노출하지 않는다.
- 역할이 없는 사용자에게 관리 버튼을 disabled로 보여주지 않고 숨긴다.
- 화면에서 숨겨도 백엔드 권한 검사는 반드시 유지한다.

## 9. 반응형 기준

| 화면 폭 | 레이아웃 |
| --- | --- |
| `< 600px` | 모바일 1열, 하단 내비게이션 |
| `600~839px` | 넓은 모바일/소형 태블릿, 선택적 2열 |
| `>= 840px` | 태블릿 2열, NavigationRail 고려 |

- 콘텐츠 최대 폭은 일반 화면 720px, 관리형 화면 1,200px를 권장한다.
- 태블릿에서 단순히 카드 폭만 늘리지 않고 목록+상세 또는 목록+편집의 2열 구조를 활용한다.
- 세로·가로 회전 시 작성 중인 입력값을 유지한다.

## 10. 접근성

- 텍스트와 배경은 WCAG AA 수준의 대비를 확보한다.
- 색상만으로 참여·마감·오류 상태를 표현하지 않는다.
- 터치 영역은 최소 48×48px로 한다.
- 아이콘 버튼에는 tooltip과 semantic label을 제공한다.
- 시스템 글자 크기 확대 시 텍스트가 잘리거나 겹치지 않게 한다.
- 카운트다운이 매초 스크린 리더에 읽히지 않도록 접근성 알림 빈도를 제한한다.
- drag 전용 기능에는 버튼 기반 대체 조작을 제공한다.

## 11. Flutter 구현 기준

- `ThemeData(useMaterial3: true)`와 테마별 `ColorScheme`을 사용한다.
- `AppColors`, `AppSpacing`, `AppRadii`, `AppTextStyles`로 token을 중앙 관리한다.
- 화면 위젯에서 같은 hex 색상이나 spacing 숫자를 반복하지 않는다.
- 공통 `AppButton`, `AppCard`, `AppTextField`, `StatusTag`, `AsyncStateView`를 만든다.
- 화면은 `SafeArea`와 키보드 inset을 고려한다.
- 버튼과 chip의 상태는 Material state를 사용해 pressed, focused, disabled를 구분한다.
- Sand Gold, Dark Blue, Icon Purple은 별도 token으로 관리하며 단순 색상 반전을 사용하지 않는다.
- iOS와 Android에서 핵심 정보 구조는 동일하게 유지하고 뒤로가기, 날짜 선택기 등 플랫폼 관습만 adaptive하게 적용한다.

## 12. UI 생성 체크리스트

새 화면이나 컴포넌트를 만들기 전에 다음을 확인한다.

- [ ] 이 화면에서 가장 중요한 정보와 행동이 하나씩 명확한가?
- [ ] 기본 배경, surface, text, primary token을 사용했는가?
- [ ] 임의의 gradient, 질감, 게임풍 장식을 추가하지 않았는가?
- [ ] 화면 좌우 여백이 16px 이상인가?
- [ ] 버튼과 아이콘의 터치 영역이 48px 이상인가?
- [ ] 색상 없이도 상태를 이해할 수 있는가?
- [ ] loading, empty, error 상태가 준비되어 있는가?
- [ ] 운영진 기능이 일반 사용자의 핵심 흐름을 방해하지 않는가?
- [ ] destructive action에 영향 범위와 확인 절차가 있는가?
- [ ] 작은 모바일 화면에서 가로 overflow가 발생하지 않는가?
- [ ] 태블릿에서 넓어진 공간을 의미 있게 활용하는가?
- [ ] 글자 크기 확대와 screen reader를 고려했는가?
- [ ] API 실패 시 입력값과 낙관적 상태를 복구하는가?
